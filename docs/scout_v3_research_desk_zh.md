# Scout v3 方案：AI 研究台与可验证的知识库（2026-10-28 确认，按阶段开发）

## 一、目标

Scout 从"规则找机会"转为**会学习的研究台**：

1. **专业分析**：AI 用完整的分析框架给出结论，并写明依据和失效条件。
2. **发现规律**：AI 从经济机制出发提出假设，用 Python 检验。
3. **行业前景**：AI 从新闻、财报、产业链等客观信息判断行业和主题的前景，提前布局。
4. **增量学习**：新的技术、策略和知识只有在对应的情境下被确认有效后，才写进知识库。

不变的原则：
- 数字只来自 Python；
- AI 写的内容要经过程序校验；
- 外部信息标明来源；
- 不按回放结果调参；
- 历史数据不裁剪；
- **Scout 不向 QuantConnect 或券商发送任何订单或指令**。

## 二、出发点：已有证据

| 结论 | 证据 |
|---|---|
| 原来的"相对持有"基准偏高（用了整段历史的平均涨幅，叠加当前成分股的偏差） | `eval_rules`，2026-10-28 |
| 7 条规则里，只有"突破回踩"（候选）在前后两半都胜过同日随机选股（t 3.8 / 3.3），但相对 SPY 只有 +0.2–0.3%：交易方式吃掉了大部分选股信息 | 同上 |
| 强势回调只在前半段有效；放量跳空、放量异动没有显著结果；趋势突破、板块轮动龙头、z 分数超跌没有优势 | 同上 |
| 价位图的回调买点前后两半都不如直接买入；突破买点必须放量收盘确认；盘中触及就买最差 | `eval_levels`，2026-10-27 |
| 出场：不分批 > 目标 1 卖 1/3 + 吊灯止损 > 目标 1、2 各卖 1/3 | `eval_exits`，2026-10-27 |
| B0：出场、择时、支撑阻力叠加 9 轮失败；B0 80% + GLD 20% 通过；TSMOM 第二引擎通过验收标准 A 和 B | B0 Optimization 会话 |

这些结论说明两件事：**假设的质量比检验的数量重要；检验必须公平而且严格**。这两点是下面设计的核心。

## 三、总体结构

```
 假设来源                     检验关                          知识库                 使用
 ───────                     ──────                          ──────                 ────
 文献 / 机制推理   ──┐
 新闻·财报·产业链 ──┼─→ 预登记 → 回测 → 批判 → 前向 → 确认 ─→ 已确认知识 ──→ AI 解读与周报（按情境调用）
 B0 的研究结果    ──┤        （不通过的写成"否定知识"）        否定知识   ──→ 提假设前先查，避免重复
 你的想法         ──┘                                         待验证     ──→ 页面标"未验证"
                                                                          ──→ 给 B0 的特征和策略规格（离线）
```

分工：AI 负责提假设、实现、检验、批判和解释；Python 负责所有数字；你批准每一次转为已确认。

## 四、知识库

### 4.1 每条知识的字段（新表 `scout.knowledge`，历史版本全部保留）

| 字段 | 含义 | 例子 |
|---|---|---|
| `kind` | 类型：`rule` 交易规则 / `feature` 特征 / `regularity` 市场规律 / `method` 分析方法 / `judgment` AI 判断类 | `rule` |
| `claim` | 一句话结论 | 突破后回踩不破的股票，未来持有期跑赢同日随机股票 |
| `mechanism` | 为什么会成立、为什么还没被套利掉 | 突破后的回踩洗掉短线获利盘，供给减少 |
| `context` | 成立的条件（JSON）：市场状态、市值、行业、持有期、流动性 | `{"regime": "any", "horizon_days": 20, "universe": "S&P 1500"}` |
| `evidence` | 检验记录：brief id、样本区间、前后两半的结果、t 值、对照方式、成本 | `rule_benchmarks` 2026-10-28 |
| `status` | 状态，见下 | `forward` |
| `polarity` | `positive` 有效 / `negative` 无效 | `positive` |
| `invalidation` | 出现什么情况就要重新检验 | 滚动 24 个月相对选股对照 t < 0 |
| `recheck_on` | 下次复查日期 | 2027-04-28 |
| `supersedes` | 取代了哪条旧知识 | — |
| `approved_by` / `approved_at` | 谁、何时批准转为已确认 | 用户 |

**状态流转**（不可跳步）：

1. `hypothesis`：已提出、已预登记；
2. `backtested`：通过回测；
3. `forward`：前向模拟中；
4. `confirmed`：你批准后确认。

旁路：任何一步不通过都转为 `rejected`，作为否定知识保留；已确认的知识复查时失效，转为 `retired`。AI 判断类知识无法回测，从 `hypothesis` 直接进入 `forward`。

### 4.2 知识怎么用

- **AI 解读和周报**：按当前情境（市场状态、行业、持有期）取出匹配的 `confirmed` 知识，写进提示词的依据部分；生成的文字必须注明引用了哪一条。`forward` 状态的知识可以展示，但页面标"未验证"。
- **提假设之前**：先检索 `rejected` 和 `retired`。换个说法重复试同一个想法，要算进同一族检验，不能当作新假设。
- **页面 `/knowledge`**：列出每条知识的状态、证据、复查日期；否定知识同样展示。

### 4.3 首批写入（来自第二节）

- **正向，`backtested`**：
  - 突破回踩的选股信息；
  - 放量收盘确认的突破买点优于盘中触及；
  - 出场：不分批、到目标 1 后才启用吊灯止损最好；
- **否定**：
  - 等回调买点不如直接买入；
  - 强势回调在后半段失效；
  - 趋势突破、板块轮动龙头、z 分数超跌没有优势；
  - B0 的 9 轮叠加。

B0 的结论在你确认后再录入。

## 五、检验关

所有门槛**现在就定下来，之后不再根据结果调整**。

| 关 | 内容 | 通过标准 |
|---|---|---|
| G0 预登记 | 跑之前先写好规格：机制、数据、规则、对照、成功标准、预期在什么情况下失效。写入知识库，状态 `hypothesis`；跑过的每一个变体都算进同一族 | 规格完整；查过否定知识，没有重复 |
| G1 回测 | 沿用并推广 `eval_rules`：同期 SPY、等权股票池、时机对照、选股对照；扣成本；前后两半分开；按市场状态拆分；检查流动性和容量；检查和已有知识的重合度（信号重合、收益相关） | 主对照前后两半都为正；全样本 t ≥ 3（参考 Harvey、Liu、Zhu 2016 对多重检验的建议）；和已确认知识的收益相关 < 0.5，否则视为同一条 |
| G2 批判 | AI 按清单逐项检查：前视偏差、幸存者偏差、数据挖掘、拥挤、成本和滑点、是否只在单一时期成立；写出反方论证 | 每一项都有结论；有未解决的问题就退回 |
| G3 前向 | 从今天起按规则记录每个信号和对照，不改参数；AI 判断类知识走判断台账 | 至少 6 个月且至少 30 个样本；前向相对对照的超额 > 0，并且不显著低于回测（差值 t > −2） |
| G4 确认 | 你看过证据后批准 | 你的决定 |
| 复查 | 已确认知识每 6 个月复查一次；也可由失效条件触发 | 滚动 24 个月的超额 t < 0，转为 `retired` |

**说明**
- **为什么要前向**：AI 的训练数据包含过去十年发生的事，用历史回测 AI 的判断，结果是被污染的。判断类知识只认前向结果。规则类知识也要前向，用来防止回测本身过拟合。
- **为什么门槛是 t ≥ 3**：这次 56 个检验里，单凭运气就会出现 2–3 个 |t| > 2。

## 六、行业与主题前景判断

### 6.1 先描述"当前的主力"（Python 计算，不做预测）

- 每周把市场收益拆解到行业和风格（动量、规模、价值、低波动）上，看是谁在推动市场；同时统计资金在行业之间的轮动，以及市场宽度。
- 这部分是描述性的，不需要验证；它是 AI 判断前景时的事实依据。

### 6.2 AI 的前景判断：重点是扩散慢的信息

- **信息来源**：
  - 多家公司财报和电话会里同时出现的趋势（资本开支、订单、库存、定价）；
  - 产业链上下游的变化；
  - 监管和政策走向；
  - 宏观数据。
- **不追单条新闻**：价格对单条新闻的反应以分钟计，追不上。

**每条判断的记录**（判断台账新增类型 `sector_thesis`）：

| 字段 | 内容 |
|---|---|
| 对象 | 行业 ETF 或主题篮子（成分由 Python 按规则确定） |
| 方向与持有期 | 偏多 / 偏空，60 或 120 个交易日 |
| 机制 | 为什么、通过什么渠道影响盈利或估值 |
| 证据 | 引用的财报段落、数据、外部报道（标"据外部报道（未经核实）"） |
| 证伪条件 | 出现什么情况说明判断错了 |
| 复盘点 | 20 / 60 / 120 个交易日 |

**打分**：对照 SPY 和等权股票池，沿用台账的打分方式，持有期新增 120 个交易日。

**频率**：周报里每周最多 3 条新判断，避免量多质低。按这个频率，要一年左右才有 30 个以上样本可以评价校准。这个慢是绕不过去的；在那之前，所有判断都标"未验证"。

### 6.3 判断方法本身也进知识库

比如"多家公司同时上调资本开支 → 上游设备行业 120 天跑赢"。这是一条 `judgment` 类知识，按 G3 走前向检验。真正被积累和验证的，是方法，而不是某一次的结论。

## 七、从数据中发现规律

- **假设先于数据**：AI 从机制出发提出候选特征，Python 计算，按点位时间保存，加入 `features.yaml`，每个都要写明含义。
- **可以用机器学习**，但必须：
  - 做滚动前推的时间序列检验，训练集和检验集之间留出隔离期；
  - 用和 G1 相同的对照；
  - 模型输出当作一条 `feature` 类知识过关。
- **不允许无约束的大规模组合搜索**；每一族检验都在 G0 登记，有明确的规模上限。

## 八、和 B0 的接口（只有离线，不自动连接）

| Scout 提供 | 形式 | B0 怎么用 |
|---|---|---|
| 已确认的特征 | 点位时间的 CSV 数据集和计算说明 | 在 QC 里离线回测，看能否改进选股或排序 |
| 策略规格 | 知识库条目导出：机制、规则、对照、证据 | B0 会话独立实现、独立回测 |
| 行业 / 主题倾向 | 只用已确认的方法产生的判断，作为给你的建议 | 由你决定是否调整 B0 的股票池或配置 |

- B0 的研究结果，无论成功还是失败，都回写到 Scout 的知识库。
- 不做实时数据接入，不向 QC 发送任何内容。将来是否接入，是单独的决定。

## 十一、风险与限制

- **AI 过度自信**：靠证据字段、批判关和前向打分约束；不让 AI 自己批准任何知识。
- **反馈慢**：行业判断要一年左右才能评价。这是方法的代价，不是缺陷。
- **知识衰减**：公开的规律会被套利掉，所以设复查日期和失效条件。
- **成本**：P4 每周多几次 AI 调用，在每月约 $30 的预算内；不为省成本牺牲质量。
- **不做的事**：自动交易；按回放结果调参；不经过关就把 AI 的判断用于配置。

## 十四、P2 实施记录（2026-10-28）

门槛（用户 2026-10-28 确认，之后不再调整）：
- 回测：主对照前后两半都为正，全样本 t 不低于 3；
- 前向验证：至少 6 个月且至少 30 个样本；
- 复查：每 6 个月一次。

同一族检验次数多时，t 门槛按 Bonferroni 上调（只升不降，10 次以内仍是 3）。

- **G0 预登记**：
  - 规格文件放在 `scout/knowledge/specs/*.yaml`，跑过之后不再修改；改了想法就换一个 key，放进同一族；
  - 每次运行记入 `scout.gate_runs`（迁移 015），按族计数；
  - 一条知识登记过规格后，不能再登记新规格。
- **G1 回测**：`scout/gate.py`，`eval_rules` 也改用它。内容包括：
  - 四种对照；
  - 前后两半、各市场状态分开看；
  - 和其他规则比较信号重合度与月度收益相关度；
  - 每条规则用自己的随机数序列，增加或调整其他规则时，不会改变这条规则的对照结果。
- **G2 批判**：AI 按 7 项清单作答，数字要能在报告里找到。没有模型时不算通过。
  - 有两项（单一时期、重复）程序能直接核对。AI 判"不通过"而报告不支持时，要求它重写。
  - **只有回测失败才会被否定**；批判不通过只是退回，状态不变，问题写进记录。
- **命令**：`python -m scout.jobs.gate register <spec>` 和 `run <key>`；报告存为 brief `gate`；`/knowledge` 显示规格和最近一次检验结果。

**验收：突破回踩**（规格是看过 10-28 的结果后补登的，已在规格里注明）。
- **第 1 次运行（本族第 1 次）**：回测四项都通过，但 AI 批判有两处误判：
  - 单一时期：看错了对照那一列；
  - 重复：把和已否定的"趋势突破"重合当成了重复。

  当时的实现又让批判失败直接否定。这三个问题都已修正，否定已撤销（版本 4，理由写在记录里）。
- **第 2 次运行（本族第 2 次）：通过，状态为"回测通过（待前向验证）"**。
  - 相对选股对照：+0.74%（t 3.63）/ +0.92%（t 3.50），全样本 +0.83%（t 5.02）；
